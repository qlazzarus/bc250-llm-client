# Local protocol 3 gate candidate

This is an isolated, uninstalled candidate based on the admission proxy in `docs/handoff/imagegen-20261107/source.tar.gz` (`backend/app/gate.py`). It does not alter the operating gate or Studio. `create_app` takes explicit state path, upstream URL and three distinct role credentials, and an optional separate upstream API key. `provision(path)` exclusively creates a new startup-held state; never run it over existing state. A single process takes a nonblocking lock for the lifetime of the gate. The state directory and its parent must be private and controlled by the operator; the candidate does not establish filesystem ownership, service identity or network restrictions.

`/control` and `/control/identity` implement role credentials and protocol 3. Upstream responses stream to the caller and remain active until the stream closes, including on cancellation or client disconnect. Every proxied request must supply `X-Model-Epoch` from `/model-snapshot`; paused or stale requests receive 409 without being queued. `/model-snapshot` checks the gate state before and after fetching upstream `/v1/models`, returning `{ready, epoch, models}`. The local Client candidate consumes this snapshot and forwards its epoch; deployment and end-to-end verification remain outstanding. Every process start durably adds the startup hold and rotates the epoch; each new switch hold also rotates the epoch; persisted holds and any recovery reservation survive restart. Recovery reservation prevents competing Studio and switch holds, and conditional releases compare epoch and relevant holds while holding the admission lock. Writes use a durable uncertainty marker, atomic replacement and fsync; after an interrupted or uncertain write the gate refuses to start until investigated. Do not remove that marker automatically.

If forwarding has started and its outcome is unknown, or closing the upstream stream fails, the gate remains unavailable and retains the active request count instead of claiming a successful drain. On restart the startup hold remains in place until an operator verifies recovery.

This is **not ready for deployment**: migrating the operating gate state requires a separately reviewed offline procedure preserving existing pause and any applicable holds and deployment generation. Studio integration and the remaining in-scope callers are not yet verified against this proxy. Loopback binding, credential provisioning, production filesystem semantics, service rollout, crash/power-loss testing and integration on the target OS remain unverified. The independent Wiki direct caller is an explicit exception to gate admission and may fail during a switch. This candidate performs no installation or server mutation.

`runtime.py` and `deploy/model-control/bc250-llm-gate-protocol3.service` are uninstalled systemd candidates. They use four systemd credential files (the upstream key file may be empty), a separately provisioned gate virtual environment under `/opt/bc250-llm-gate`, and pre-provisioned state under `/var/lib/bc250-llm-gate`; the service never provisions or migrates state itself. This gate tree is separate from the worker bootstrap's strictly checked `/opt/bc250-model-control` tree. `migration.provision_from_legacy_snapshot` converts a verified drained legacy status into new state, preserving legacy pause and refusing overwrite. It does not prove the old gate has stopped or exclude concurrent controllers. The template requires a separately prepared service-writable state directory and is not an instruction to replace the operating unit. Its paths and permissions must be verified on the target host.

Run the local tests with `PYTHONPATH=. .venv/bin/pytest -q tests/test_gate_candidate_protocol3.py tests/test_worker_gate.py tests/test_worker_recovery_reservation.py`.
