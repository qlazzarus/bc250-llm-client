# 구현과 검증 TODO

현재 기능은 [구성 문서](architecture.md)에 기술한다. 이 문서는 아직 필요한 구현과 운영 검증만 관리한다. 코드를 구현하는 작업, 실제 서버에서 검증하는 작업, 별도 요구사항 결정이 필요한 확장을 구분한다. 완료한 항목은 여기서 제거하고 해당 구성 문서에 최종 동작만 반영한다.

## 최우선 작업

[컨텍스트 보존 구현 Task](tasks/context-preservation.md)를 다른 작업보다 먼저 진행한다. 사용량·남은량 바, 압축 상태, 초장문 분할·구조화 기억·원문 검색·복구와 실모델 검증을 CT01~20으로 나눴다. 실행 담당은 DeepSeek 4.1 Flash이며 한 번에 한 Task만 수행한다. 주요 기억 조회 UI는 문서의 리뷰를 보고 범위를 확정하는 선택 항목이다.

## 공유 Wiki 구현과 제품 결정

- [ ] **W1 검색·발췌 품질 보강** — 운영 평가에서 확인되는 동의어·복잡한 조사·다중 근거 누락을 대상으로 개선한다. 현재 명시적 Alias, BC250 정규화, FTS5, 조사형 발췌 기능을 다시 신규 구현 과제로 취급하지 않는다. 같은 자료에서 Recall@3·무관 결과율·발췌 포함률·지연을 비교한다.
- [ ] **W2 사용자 식별과 개인 기억 범위 결정** — 가족 사용자 식별, 개인/공유 범위, 접근 권한, 사용자별 선호와 여러 기기 동기화 정책을 먼저 정한다. 이 결정 전에는 공유 기억에 개인 정보를 추정 저장하지 않는다. 인증·소유권·삭제·내보내기 계약을 정한 후 구현한다.
- [ ] **W3 개별 출처 삭제 정책** — 단독 메시지 삭제 기능을 도입할 경우 관련 기억 redaction·격리·문서 참조와 삭제 이력을 설계한다. 현재 대화 삭제 정책과 충돌하지 않아야 한다. 메시지 삭제 API 자체를 이미 제공한다고 가정하지 않는다.

## 설정과 동시성 확장

- [ ] **M1 worker 계정 설정 일반화** — runtime의 고정 Client 계정과 socket peer/group 정책을 설정으로 묶는다. 잘못된 UID·group·권한을 거절하는 설치 및 회귀 검사를 포함한다.
- [ ] **M2 배포와 전환의 자동 상호 배제** — 단일 관리자 수동 조율을 넘어 자동 배포가 필요한 경우 배포/restart와 모델 전환의 강제 잠금 계약을 설계한다. worker·gate·Client 배포 중단과 불명 상태에서도 잘못된 성공·hold 해제가 없어야 한다.
- [ ] **M3 다중 호스트 지원 여부 결정** — 필요성이 확정되면 요약 OS 파일 잠금 대신 lease/heartbeat/fencing과 전역 생성 동시성을 설계한다. 현재 한 호스트의 로컬 SQLite/flock 계약을 그대로 분산 환경에 확장하지 않는다.

## 운영 전환과 복구 검증

다음은 이미 존재하는 코드를 실제 환경에서 검증하거나 설정하는 작업이다. 현재 서버 상태를 재조회하고 필요한 범위만 수행한다. 과거 설치 전 기록을 근거로 서비스가 없다고 단정하거나 이미 운영 중인 기능을 다시 설치하지 않는다.

- [ ] **O2 통합 Wiki 전환 상태 정합성** — 유효 WIKI_STORE, 외부 호출자, 구 writer·구 release의 재부팅/재배포 경로, DB·앱 백업 복원 가능성을 확인한다. 필요시 구 writer의 지속 차단을 구현·적용한다. 통합 writer 하나만 사용하고 store_id 없는 구 코드가 새 데이터를 쓰지 못해야 한다. 별도 Wiki 서비스 종료·데이터 import/삭제는 자동 실행 범위가 아니다.
- [ ] **O3 Wiki 실제 화면과 사용자 흐름** — 장문 제공 → 제안 → 거절/초안 편집 → 중복 확인 → 명시 저장 → 검색·인용 흐름을 실제 브라우저/API로 연결해 검사한다. 모바일 폭, PC 키보드, 포커스 복귀, 긴 표·본문과 사용자의 이해도를 포함한다.
- [ ] **O4 검색·기억 평가** — 비민감 문서/질의 20~30개와 음성 사례로 Recall@3, 무관 결과율, 저장 precision/recall, retrieved/provided/cited 차이, 주장의 의미적 근거 일치를 측정한다. 토큰·SQL·메모리와 지연 p50/p95를 함께 기록한다. 작은 mock fixture의 수치를 운영 품질로 대신하지 않는다.
- [ ] **O5 모델·이미지 동시성과 장애 복구** — 실제 Studio GPU 작업과 모델 전환 경합, drain, pause/owned hold, 프로세스 종료·restart·응답 유실·정리 중단을 격리된 검증 범위에서 검사한다. 실제 운영 백업 전체 복원을 별도 환경에서 리허설한다. 운영 장애 주입은 명시적으로 정한 창과 복구 절차 안에서 수행한다.
- [ ] **O6 이미지 품질과 연동 확인** — 실행 모델별 JSON schema/reasoning 제어, 번역 충실도·exact_text, 프리셋과 지원 옵션, MOSS LoRA ON/OFF capability·작업 snapshot·LLM 복귀를 검사한다. Client의 지원 표시와 실제 GPU 품질을 구분한다.
- [ ] **O7 테스트 자료 관리** — 운영에 생성한 검증용 대화·문서의 소유자와 보존 필요성을 확인한다. 확인된 검증 자료만 정리하며 과거 문서에 적힌 개수나 ID를 현재 삭제 대상으로 간주하지 않는다.

## 범위 밖으로 유지하는 항목

- 외부 Wiki용 조건부 API 패치 배포는 통합 Wiki 구현의 선행 과제가 아니다.
- 전체 origin 자산 provenance, 별도 서비스 UID 강제 분리, root 전용 독립 배포 승격 및 과거 DB 차단 VM 연구는 현재 단일 관리자 기능의 필수 조건이 아니다.
- 새 벡터 DB·임베딩 서비스, 모든 공유 속성의 자유형 자동 기억, 다중 호스트 운영은 별도 요구 없이 추가하지 않는다.

## 공통 완료 기준

코드 작업은 관련 회귀와 전체 영향 범위를 검사하고 현재 구성 설명에 최종 계약을 반영한다. 실기 검증은 모델·유효 설정·입력 조건·측정 결과와 한계를 남긴다. 검증 기록을 기능 설명에 시간순으로 누적하지 않는다. 미해결 항목만 이 TODO에 유지한다.
