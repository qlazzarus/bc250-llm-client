# 공유 Wiki와 기억

## 저장소와 공유 범위

`WIKI_STORE=integrated`는 Client SQLite의 문서·검색·기억 repository를 사용한다. `legacy_external`은 외부 Wiki HTTP 어댑터를 사용하며 설정 기본값이다. 두 저장소의 문서 ID는 별개 namespace이며 과거 참조를 새 문서로 자동 연결하지 않는다.

앱 사용자는 같은 Wiki와 공유 기억을 보고 편집한다. 사용자 식별·개인 기억·계정별 접근 제어는 제공하지 않는다. 사용자 식별이 필요한 `나`의 선호를 통합 자동 기억으로 추정하지 않는다.

## 문서 관리와 주소

통합 Wiki는 목록·검색·읽기·생성·수정·삭제, 별칭 편집, 최근 100개 revision 목록과 diff를 제공한다. 문서 수정·삭제·별칭 변경에는 expected_revision을 사용한다. 동일 revision의 경쟁 수정은 하나만 성공하고 다른 요청은 409가 된다.

주소는 `/llm/wiki/{분류}/{세부 분류}/{제목}`이며 편집·별칭·이력은 `?view=edit`, `?view=aliases`, `?view=history`다. 문서 내부 ID는 유지하며 제목·분류를 변경해도 기존 경로로 같은 문서를 찾는다. 삭제한 주소는 다른 문서에 재사용하지 않는다. 주소 충돌은 ID 등을 붙여 구분한다. 기존 ID 및 hash 주소도 호환 처리한다.

대화 주소는 `/llm/chat/{대화 ID}`다. Caddy의 SPA fallback이 있어야 직접 링크와 새로고침이 동작한다.

## 메시지에서 문서 저장

사용자 메시지의 장문 자료는 문서 초안으로 열어 제목·본문·출처를 편집할 수 있다. 저장 제안 자체는 쓰기 작업이 아니다. 기존 문서와 중복을 확인한 뒤 명시적 최종 저장을 수행한다. 요청 ID로 중복 제출을 구분하며 기존 문서 갱신에는 revision을 사용한다.

직전 추가 정보 요청과 현재 사용자 발언을 연결하는 저장 제안을 제공한다. 제안 거절 상태는 브라우저 화면에만 유지될 수 있다. 일반 문서 저장과 좁은 공유 속성 자동 기억은 서로 다른 경로다.

## 검색과 근거

통합 검색은 정규화된 제목·명시적 별칭, FTS5와 부분 문자열 후보를 사용한다. NFKC/casefold 및 BC250 표기 정규화는 조회용이며 원문을 바꾸지 않는다. 별칭은 사용자가 명시적으로 등록한다. 충돌 별칭이 있으면 임의의 문서를 선택하지 않는다.

짧고 명확한 후속 질문에는 직전 사용자 질문을 보강한다. 독립 질문에 이전 대화를 무조건 붙이지 않는다. 질문 단어의 관련 구간을 골라 최대 세 문서에서 각각 최대 1000자를 발췌한다. 제한된 한국어 조사 제거와 희소 단어 우선 선택을 사용하며 의미 기반 검색이나 일반 형태소 분석은 아니다.

근거 화면은 다음을 구분한다.

- retrieved: 검색된 문서
- provided: 최종 프롬프트에 실제 포함된 발췌
- cited: 답변에서 식별한 인용
- invalid citations: 제공되지 않았거나 연결할 수 없는 인용

숫자·문서 ID·지원되는 제목 인용을 해석하지만 인용 표기 일치가 사실성이나 주장과 근거의 의미적 일치를 보장하지 않는다. 예산 때문에 제외된 자료는 provided로 표시하지 않는다. 문서 변경 뒤에도 해당 답변의 근거 snapshot을 조회할 수 있다.

## 통합 자동 기억

[SHARED_SLOTS](../backend/app/memory_repository.py)는 다음 네 공유 속성을 허용한다.

| 대상 | 속성 |
|---|---|
| BC250 서버 | 운영체제, 백업 경로, 백업 주기 |
| BC250 Client | 서비스 포트 |

통합 경로는 정규식 기반 매핑과 SQLite를 사용하며 기억 분류를 위한 추가 LLM 호출을 하지 않는다. 사용자 원문 span을 검증하고 질문·추측·모호한 대상은 저장하지 않는다. Assistant의 문장을 사용자 진술로 저장하지 않는다.

새 값과 기존 값이 충돌하면 확인 정책을 적용하고 확인은 대상·revision·후보·출처에 연결한다. 문서 변경, 활성 기억 변경, 작업 결과는 한 DB transaction에서 처리한다. 출처 대화가 삭제되면 관련 기억의 출처 redaction·격리 정책을 적용한다. 비활성·격리 기억은 검색 근거에서 제외한다.

기억 UI는 간단한 상태와 필요한 상세 기록을 분리한다. 확인 대기·실패·결과 불명 상태를 성공으로 표시하지 않는다. 검색 참고와 자동 기억 설정은 브라우저에 저장하며 다른 기기에 동기화하지 않는다. 명시적 기억 요청은 자동 기억 스위치와 별도로 처리한다.

## 외부 Wiki 모드

외부 어댑터는 loopback Wiki API를 호출하며 `/api/ask`로 llama를 직접 호출하지 않는다. 일반 대화 검색과 기억만 사용하고 롤플레잉·이미지 프롬프트에서는 검색하지 않는다.

외부 자동 기억은 LLM gate로 분류하고 사용자 원문의 연속된 구간만 저장한다. 정정 대상은 기존 문서에 정확히 한 번 존재해야 한다. HTTP 쓰기 결과가 불명하면 자동 재전송하지 않는다. 외부 API에 원자적 조건부 갱신이 없으면 동시 수정의 덮어쓰기 위험이 있다. 내부 저장소의 transaction 보장을 외부 모드에 적용된 것으로 해석하지 않는다.
