# 가족 Wiki 연동 계획

## 2026-11-12 실행 계획

질문 원문 저장 방지, 선별 자동 기억, 중복·갱신, 출처 추적 및 기억 UI/스크롤 개선은 [Wiki RAG·자동 기억 실행 계획](wiki-memory-execution-plan.md)을 따른다. W00~W07은 구현·검증 이력과 남은 검증 제약을 해당 문서에서 확인한다.

W08 목표 계약은 기존 Client SQLite를 메타데이터와 작업 조정에 재사용하고 Wiki는 본문 저장소로 유지한다. 개인 기억·여러 기기와 선호·가족 사용자 식별은 [후속 TODO](wiki-memory-execution-plan.md#421a-후속-todo--개인-기억과-가족-확장-현재-범위-아님)이며 현재 W09 범위가 아니다. legacy Wiki 문서는 자동 기억으로 승격하지 않는다. 출처 삭제 시 Client 메타데이터는 redaction하고 관련 Wiki 문서는 자동 삭제하지 않고 검색에서 격리한다. 새 writer는 Wiki의 CAS·멱등성·결과 조회 및 관리 문서 검색 필터가 검증되기 전 활성화하지 않는다. 이는 목표 설계이며 현재 writer가 이 보장을 제공한다는 뜻이 아니다.

아래 내용은 기존 동작과 이전 검토 이력이다. 아래 Wiki 통합/별도 서비스 종료 TODO는 새 실행 계획의 선행 조건이 아니며, 이번 범위에서는 기존 Wiki·Client SQLite·gate를 재사용한다.

1. 같은 서버의 loopback Wiki API를 클라이언트 백엔드에서 호출한다. 문서 관리 화면은 클라이언트에서 제공하지 않는다.
2. 일반 대화에서 선택적으로 검색해 제한된 발췌를 기존 gate의 컨텍스트 예산에 포함한다. 검색된 자료와 수정 시각을 답변에 남긴다.
3. 일반 대화에서 LLM은 사용자 발언의 원문을 선택해 Wiki에 자동으로 기록할 수 있다.
4. 실제 서버에서 한국어 검색 예시, 긴 문서, 서비스 중단, 문서 변경 및 gate 대기 상황을 확인한다.

후속 개선: Wiki 서버의 원자적 조건부 갱신과 버전 이력, 한국어 검색 평가 및 문서 청크 검색. 현재 서버 API는 갱신의 원자적 충돌 방지를 제공하지 않는다.
