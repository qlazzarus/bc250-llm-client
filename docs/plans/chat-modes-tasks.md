# BC-250 채팅 모드 개선 — Terra Medium 실행 태스크

## 목적과 실행 규칙

빠른 질문, 롤플레잉, 이미지 프롬프트의 세 모드를 제공하고 컨텍스트 관리와 채팅 UI를 개선한다. 이 문서는 구현 계획이며 현재 구현 완료를 의미하지 않는다.

- 한 번에 하나의 태스크를 수행한다. 아래 순서를 기본으로 하고 의존 태스크의 완료 조건부터 확인한다.
- 시작할 때 해당 파일과 기존 변경 사항을 읽는다. 문서의 파일 목록은 탐색 시작점이며 실제 코드를 우선한다.
- 각 태스크 종료 시 변경 파일, 검증 결과, 미해결 사항, 다음 태스크를 보고한다. 실행하지 않은 테스트를 통과했다고 보고하지 않는다.
- 모델 서버, gate, Art Studio, Caddy 또는 systemd의 운영 설정 변경과 실제 배포는 이 구현 작업에 포함하지 않는다.
- 브라우저는 `/llm/api/v1`만 호출한다. 백엔드만 gate를 호출하며 llama-server 또는 Studio에 직접 연결하지 않는다.
- 모든 보호 API는 단일 APP_API_KEY 인증을 유지한다. 별도 관리자 키와 모델 선택 UI를 되살리지 않는다.
- 추론은 기본 OFF로 유지하고 reasoning_content는 저장하거나 브라우저로 전달하지 않는다.
- 새로운 의존성은 필요한 경우에만 추가하고 lockfile을 함께 갱신한다.

## 제품 결정

| 모드 ID | 이름 | 모델에 전달할 컨텍스트 | 기본 출력 상한 |
|---|---|---|---|
| quick | 빠른 질문 | 모드 지시 + 현재 질문만 | 512 |
| roleplay | 롤플레잉 | 고정 설정 + 이야기 요약 + 최근 완료 대화 + 현재 질문 | 1024 |
| image_prompt | 이미지 프롬프트 | 구조화된 이미지 설정 + 최근 완료 대화 + 현재 질문 | 1024 |

- 출력 길이 선택은 짧게 512 / 보통 1024 / 길게 2048 토큰으로 시작한다. 서버 상한을 넘길 수 없다. BC-250에서 성능 검증 전까지 임시 기준으로 표시한다.
- 빠른 질문도 화면과 DB에는 대화가 남지만 이전 메시지는 모델에 전달하지 않는다. 화면에 이 차이를 설명한다.
- 롤플레잉 설정: 캐릭터, 세계관, 말투/응답 규칙, 현재 상황. 이야기 요약은 조회·수정 가능하게 한다.
- 이미지 프롬프트 설정: 주제, 구도, 스타일, 조명, 색감, 제외 요소, 출력 언어. 실제 이미지 생성이나 Studio 호출은 범위 밖이다.
- 모드는 새 대화 생성 시 선택하고 생성 후 고정한다. 다른 모드는 새 대화로 시작한다.
- 기존 대화는 `mode=quick`, `context_policy=recent`로 마이그레이션해 이전 최근 대화 동작을 보존한다. 새 quick 대화는 `context_policy=none`이다. 기존 대화에는 '이전 대화 포함' 표시를 둔다.
- 모델은 서버가 gate의 모델 목록에서 확인해 선택한다. UI는 모델 선택을 제공하지 않고 시스템 상태에서만 정보를 보여준다.
- 추론 레벨 선택은 이번 범위에서 제외한다. 현재 검증된 enable_thinking=false 동작을 유지한다.

## T01 — 기존 동작 계약과 회귀 테스트

의존성: 없음.

시작 파일: backend/app/main.py, config.py, db.py, tests/test_api.py, frontend/src/api.ts.

작업:
- 현재 인증, 메시지 저장 순서, non-stream/stream 분기, SSE 이벤트 계약을 정리한다.
- gate 모킹으로 인증 실패, reasoning 비노출, non-thinking payload, 정상 스트리밍과 reasoning-only 종료를 검증하는 회귀 테스트를 추가한다.
- 테스트는 임시 DB를 사용하고 실제 gate나 GPU에 요청하지 않는다.

완료 조건: 기존 기능의 기준 테스트가 통과하고 알려진 결함은 테스트 결과 또는 문서에 명시되어 있다.

## T02 — 모드·설정·마이그레이션

의존성: T01.

시작 파일: db.py, main.py의 대화 CRUD, frontend/src/api.ts의 타입.

작업:
- 대화에 mode, context_policy, mode_settings, response_length, summary와 요약 기준 위치를 저장한다.
- 모델별로 다른 것이 아니라 모드별 설정을 검증하는 명시적 요청 스키마를 만든다. 길이 상한과 허용 필드를 정의한다.
- 새 대화 생성에서 모드를 지정하고 조회 응답에 설정을 포함한다. 설정 변경 API는 모드 변경을 허용하지 않는다.
- SQLite 스키마 버전을 관리하고 기존 DB를 반복 실행해도 안전하게 마이그레이션한다.
- 기존 대화 보존 정책은 위 제품 결정을 따른다.

완료 조건: 신규/기존 DB 모두 정상이며 기존 메시지 손실이 없다. 잘못된 모드·설정은 일관된 JSON 오류로 거절된다. 마이그레이션 테스트 통과.

## T03 — 생성 요청 수명주기와 재시도

의존성: T02.

작업:
- 요청 ID와 pending/completed/failed/cancelled 상태를 저장한다. 성공한 사용자·assistant 쌍을 식별할 수 있게 한다.
- 재시도는 같은 질문을 DB에 중복 추가하지 않는다. 기존 완료 요청의 재전송도 중복 생성하지 않는다.
- 같은 대화의 동시 생성을 제어하고 생성 도중 삭제와 저장 사이 충돌을 처리한다.
- 실패·취소된 시도의 부분 답변은 완료된 히스토리에 포함하지 않는다.
- 스트리밍의 done/error 계약을 명확히 한다. done 없이 연결이 끝난 경우 성공으로 처리하지 않는다.
- 브라우저 취소 시 gate 연결을 정리한다. 실제 GPU 생성 중단은 gate 지원 여부에 따라 다름을 명시한다.

완료 조건: 중복 전송, 실패 후 재시도, 중간 연결 종료, 취소, 동일 대화 동시 요청 테스트 통과. 세마포어와 HTTP 연결이 해제된다.

## T04 — 모드별 프롬프트·컨텍스트 서비스

의존성: T02, T03.

작업:
- 라우트에서 프롬프트 조립을 분리해 독립적인 서비스로 만든다. stream/non-stream이 같은 조립 경로를 사용한다.
- quick은 현재 질문만, roleplay/image_prompt는 고정 설정과 최근 완료된 턴을 포함한다. 현재 질문을 두 번 넣지 않는다.
- 고정 설정은 보존하고 오래된 턴부터 제외한다. 메시지 개수 제한에 더해 입력 토큰 예산을 적용한다.
- 입력 예산 = 확인된 서버 컨텍스트 한도 - 출력 예약 - 안전 여유. 토큰 계산 기능은 gate가 지원하는 경우에만 활용하며 8080을 우회 호출하지 않는다.
- 정확한 토큰 계산이 불가능하면 보수적 추정임을 명시한다. 서버 컨텍스트 크기는 모델 홍보 스펙으로 추정하지 않고 서버 설정값으로 받는다.
- 현재 질문이나 필수 설정 자체가 예산을 초과하면 조용히 잘라 보내지 말고 설명 가능한 오류를 반환한다.
- 백엔드가 `/v1/models`를 통해 모델 ID를 확인하도록 한다. 브라우저가 모델 경로나 ID를 선택하는 의존성을 제거한다.

완료 조건: 동일 방 기억 유지, 다른 방 격리, quick 히스토리 제외, 기존 대화 recent 유지, 예산 초과와 턴 경계 보존 테스트 통과.

## T05 — 응답 길이·종료 사유·실행 정보

의존성: T04.

작업:
- 모드 기본 길이와 사용자 선택 길이를 서버 허용 범위 안에서 적용한다.
- 요청 프롬프트에 기대 답변 길이를 반영하되 토큰 상한과 실제 길이가 같지 않음을 UI에 설명한다.
- enable_thinking=false 정책을 공통 경로에서 유지한다.
- finish_reason=length를 완료와 구분하고 '답변 길이 제한에 도달했습니다'로 표시할 정보를 반환한다.
- reasoning-only, gate 오류, 응답 형식 오류, 정상 답변을 구분한다. 추론 원문은 전달하지 않는다.
- 가능한 경우 첫 최종 답변 시간, 생성 시간, usage를 수집한다. gate 대기 시간은 근거가 없으면 추정값으로 단정하지 않는다.

완료 조건: 길이별 payload, 상한 적용, 길이 종료, 빈 답변, gate 오류의 테스트 통과. 원문·키를 로그에 남기지 않는다.

## T08 — 자동 스크롤과 스트리밍 렌더링

의존성: T07.

작업:
- 사용자가 하단에 있을 때만 새 토큰을 따라간다. 위로 스크롤하면 따라가기를 중단한다.
- 직접 메시지를 전송하면 최신 메시지로 이동하고 '최신 메시지로' 버튼으로 따라가기를 재개한다.
- 토큰마다 전체 목록을 재생성하지 않도록 완료 메시지를 메모화하고 스트리밍 메시지 갱신을 분리한다.
- 토큰 변경을 짧은 간격 또는 프레임 단위로 묶는다. 매 토큰 smooth-scroll 애니메이션을 실행하지 않는다.
- 대화 변경 시 이전 스트림의 스크롤 이벤트가 새 대화에 적용되지 않게 한다.

완료 조건: 하단 추적, 과거 대화 읽기, 긴 코드블록 높이 변화, 대화 전환을 브라우저에서 검증한다. 완료된 과거 메시지가 토큰마다 다시 Markdown 파싱되지 않는다.

## T09 — 메시지 페이지 조회와 긴 대화 가상화

의존성: T03, T08.

작업:
- 메시지를 안정된 순서의 커서 기반으로 조회한다. 최근 페이지부터 표시하고 위로 이동할 때 이전 페이지를 불러온다.
- 대화 메타데이터 조회와 전체 메시지 로딩을 분리한다. 완료 이벤트 이후 전체 대화를 다시 받지 않는다.
- 가변 높이 Markdown과 스트리밍 메시지를 지원하는 가상 목록을 적용한다.
- 과거 메시지를 추가할 때 스크롤 기준 위치를 보존한다.
- 모델에 보낼 컨텍스트는 서버 DB 기준으로 구성한다. 브라우저에 로드된 페이지와 독립적이어야 한다.

완료 조건: 1,000개 메시지 fixture로 입력·스크롤·스트리밍을 측정한다. DOM 메시지 수가 전체 개수에 비례해 증가하지 않고 페이지 중복/누락과 스크롤 점프가 없다.

## T10 — 롤플레잉 장기 기억

의존성: T04, T05, T06.

작업:
- 고정 캐릭터/세계관과 변경 가능한 이야기 요약을 분리한다. 사용자가 요약을 조회·수정할 수 있게 한다.
- 요약 대상 범위를 저장해 최근 턴과 중복되지 않게 한다.
- 예산 임계점에서만 gate 경유 요약을 수행한다. 사용자 답변과 요약 요청을 중첩 실행하지 않는다.
- 요약 실패 시 기존 요약을 보존하고 제한된 최근 히스토리로 동작한다.
- 요약은 실패/취소된 시도를 제외하고 GPU image_priority와 기존 gate 직렬화를 따른다.
- 이미지 프롬프트는 우선 구조화된 설정과 최근 턴만 사용하고 자동 요약은 적용하지 않는다.

완료 조건: 긴 이야기에서 고정 설정 보존, 요약 범위 중복 방지, 수동 수정, 요약 실패 fallback, 다른 대화와 격리 검증.

## T11 — BC-250 실제 검증과 배포 문서

의존성: T01~T10.

작업:
- 단위/통합 테스트, frontend lint/build를 실행한다.
- 실제 검증은 사용자 서버 접근이 가능한 시점에 별도로 수행한다. 접근이 없으면 미검증 항목으로 남긴다.
- 실제 컨텍스트 한도와 gate 버전을 확인하고 짧게/보통/길게 및 세 모드의 첫 답변 시간·생성 시간·메모리 사용을 측정한다.
- 이미지 작업 중 대기와 작업 종료 후 응답 재개를 검증한다. 운영 이미지 작업을 임의로 시작하거나 중단하지 않는다.
- 측정값에 따라 기본 예산을 확정한다. 생성 동시성은 gate 정책과 관측값에 맞추며 무조건 높이지 않는다.
- SCP 외부 포트 2222, 백업, 서비스 중지, DB 백업/마이그레이션, 재시작, 검증, 롤백 절차를 문서화한다.
- 스키마 변경 이후 롤백은 구버전 코드만 복원하지 않고 해당 백업 DB와 함께 복원해야 함을 명시한다.

완료 조건: 회귀 테스트 통과, 측정 결과 또는 서버 미검증 목록, 배포/롤백 가이드가 준비되어 있다. 실제 배포 여부는 별도로 보고한다.
