# 모델별 추론 정책과 검증 기준 — M2-03

기준: 2026-11-07 운영 모델 설정의 읽기 전용 조사, 현재 로드 모델의 상태 조회, Client 코드 검토. M2-03은 모델 프로필·검증 기준의 설계다. 설정값이나 설계 완료를 실제 추론 호환성·운영 전환 성공으로 간주하지 않는다. 전체 상태는 [통합 계획 §7](llm-model-switch-plan.md#7-실행-체크리스트와-완료-조건)을 따른다.

## 2. 신뢰된 모델 프로필

신뢰된 root 소유 모델 설정은 관리 이름, GGUF 경로 ID, 설정 context와 parallel의 기준이다. 파일은 기존 `ModelRegistry`의 소유권·경로·형식 검사를 통과해야 하며 임의 shell 설정은 실행하지 않는다. 설정은 현재 로드 상태의 증거가 아니다. 실제 모델이 준비됐는지, 관리 이름의 GGUF ID와 로드 ID가 일치하는지 및 실제 슬롯별 `n_ctx`는 작업자/검증된 gate를 통해 확인한다. 슬롯이 여러 개일 때 설정 context를 단순히 슬롯 수로 나눈 값을 확정값으로 가정하지 않고 실제 사용 가능한 슬롯 context를 확인한다.

Client 서버 내부의 요청별 프로필은 최소한 `{관리 이름, 로드 ID, 설정 context, 실제 슬롯 context, 유효 context, epoch, 기능 검증 상태}`를 포함한다. 유효 context는 설정의 전체 상한, Client 운영 상한과 **확인된 실제 per-slot context의 최솟값**을 넘지 않는다. 프로필의 생성·전달은 root가 검증한 설정과 실제 로드 snapshot을 묶는 내부 계약으로 구현하고, 일반 브라우저가 임의 경로·context·기능 지원값을 지정할 수 없게 한다. GGUF 절대 경로와 서버 설정은 관리 UI에 추가로 노출하지 않는다.

설정·실제 로드 모델·slot context·epoch를 확인할 수 없거나 서로 맞지 않으면 새 모델 추론을 보류 또는 안전한 오류로 거절한다. 모델 ID를 임의 alias나 경로의 basename만으로 동일하다고 판단하지 않는다. 이미 사용하는 서버의 비활성 기본 설정과 개발 환경에 대해서는 M5에서 명시적인 기존 동작 호환·실패 정책을 시험한다. 프로필 동기화 기능이 없는데 임의 기본값 16384로 전환 기능을 활성화하지 않는다.

기능 메타데이터는 개별 모델의 **정확한 GGUF와 실행 설정, llama-server 빌드·chat template**에 대한 검증 근거에 연결한다. 파일이나 빌드·템플릿이 바뀌면 이전 기능 인증을 재사용하지 않는다. 증거가 없는 JSON schema 및 reasoning 제어는 `unknown`으로 표시하고 `supported`로 추정하지 않는다. 별도 추론 요청의 요구 옵션이 검증되지 않았다면 해당 기능을 안전한 오류로 중단하고 원래 요청의 요구를 조용히 약화하지 않는다. 테스트 결과를 얻은 뒤에만 해당 조합을 활성화한다.

## 3. 모델 추종과 전환 경합

- 모델 전환 기능을 켠 운영 구성은 `LLM_MODEL_ID`를 비워 활성 모델을 따르며, 고정 ID가 설정된 경우 전환 활성화 전 명확하게 차단한다. 기존 고정 설정의 다른 사용 사례를 무단으로 바꾸지 않고 M5에서 비활성 모드의 호환을 검증한다. 현재 운영 프로세스의 값은 빈 문자열이었다.
- 각 추론 진입은 준비된 모델 snapshot과 프로필·epoch를 새로 확보한다. Client가 오래된 snapshot을 캐시한 채 전환이 진행될 수 있으므로 마지막 판정은 M2-02 protocol 3 gate의 epoch 검사와 입장 처리에서 원자적으로 한다. epoch가 불일치하거나 전환 중이면 요청을 거절하고 초안을 보존한다. 일부 응답이 전달된 요청을 자동 재전송하지 않는다.
- 실행 대기 중인 제목·요약 등은 추론 직전에 프로필을 다시 확보한다. 이미지 의도 분석과 뒤이은 프롬프트 생성처럼 여러 단계가 있는 경우 각 단계의 모델과 epoch를 명시적으로 검증한다. 중간에 변경되면 이전 결과를 무조건 새 모델에 이어 붙이지 않고, 기능별로 안전한 재시작 또는 사용자에게 명확한 실패로 처리한다.
- 각 경로의 사용자 표시, 작업 상태 및 오류가 모델 전환·재조회 실패를 정확히 반영해야 한다. 이전 모델로 준비된 payload가 새로운 모델에 무심코 재사용되지 않게 한다.

## 4. 토큰 예산과 요청 경로

기존 `estimate_tokens()`는 UTF-8 바이트 길이/2의 휴리스틱이다. tokenizer·chat template·role framing·schema overhead를 전부 보수적으로 상한 보장한다는 근거는 없다. 따라서 추정값만으로 실제 모델 context 초과가 불가능하다고 주장하지 않는다.

M5-01은 선택된 실제 모델·template에 대응하는 검증된 token 계산 경로를 사용해 **최종 메시지·template framing·필요한 schema 및 출력 예약·safety margin**을 확인한다. 출력 예약은 사용자에게 보이는 답변뿐 아니라 hidden reasoning을 포함한 서버 생성 총 토큰의 검증된 상한이다. Qwen 3.6의 auto/-1 또는 Qwen 3.5의 reasoning 미설정만으로 이 상한이 보장된다고 판단하지 않으며, 상한을 확인할 수 없는 reasoning 요구 경로는 차단한다. 계산을 신뢰할 수 없거나 모델/epoch가 바뀌면 예산 확인 불가로 안전하게 거절한다. 모델의 실제 서버가 context 초과 또는 token 계산 오류를 반환하는 경우에도 오류를 사용자에게 표시하고 자동으로 내용을 잘라 재전송하지 않는다. tokenizer 비용·지원 여부와 어떤 경로로 실제 chat template을 적용할지는 최종 구현과 M6 검증에서 확정하며 임의 정확도를 가정하지 않는다.

구조화 응답의 재시도는 추가 지시와 기존 실패 출력까지 포함한 **매 시도의 최종 payload**를 새 모델 snapshot·epoch 기준으로 다시 계산한다. timeout이나 부분 응답으로 결과가 불명확한 요청은 자동 재시도하지 않는다.

| Client 추론 경로 | 필요한 적용 |
| --- | --- |
| 일반·롤플레잉 대화와 스트리밍 | 같은 snapshot의 프로필로 필수 system/현재 메시지와 완결된 과거 턴을 예산 내에서 구성. 전환 거절 시 초안·기존 응답 보존 |
| 자동 제목 | 최종 지시문과 출력 예산까지 검사. 전환 중 보류·실패가 대화 성공을 취소하지 않음 |
| 장기 요약 | 기존 요약·지시문·전사 전체와 출력 예산을 포함. 큐에 넣을 당시의 범위를 새 모델 context로 다시 선택하고 실제 요약한 마지막 메시지까지만 cursor를 확정 |
| Client Wiki 메모리 판단 및 Wiki 초안 | Client 내부 추론 경로로 프로필·epoch 및 schema 요구를 검사. 독립 Wiki의 직접 llama API는 사용자 지정 예외 |
| 이미지 의도 분석·프롬프트 생성 | 각 단계의 프로필/epoch와 strict schema 검증 상태를 확인하고 출력 예산 검사. 원본 직접 모드처럼 LLM 추론이 없는 경로는 별도로 유지 |

예를 들어 현재 Client 상한 16384로 Qwen 3.5의 설정 context 4096을 초과해 요청을 허용하지 않는다. 실제 slot context가 4096보다 작으면 더 작은 확인값을 사용한다. 기존 summary trigger 5000은 4096 context보다 크므로 요약 트리거·청크 정책도 모델별 예산에 맞게 검토한다.

## 5. 수용 기준과 실행 단계

1. **M5-01 단위·통합:** 네 모델 설정을 읽고 식별·context를 매핑하며, 실제 slot context와 설정의 작은 값을 사용한다. 누락·잘못된 설정, loaded ID 불일치, 알려지지 않은 모델/기능 및 인증·조회 실패는 추론 전에 안전하게 처리한다. `LLM_MODEL_ID` 고정 상태에서 전환 활성화를 거절한다.
2. **전 경로 예산:** 제목·요약·Wiki 메모리·Wiki 초안·이미지 의도/프롬프트·일반 채팅의 최종 payload와 출력 예산을 검증한다. 4096 경계, template·schema overhead 및 멀티바이트 입력, 요약 재선정·cursor 보존, 모델 전환 전후의 대기 작업을 포함한다. fallback 추정의 오차를 감추지 않는다.
3. **M5-02 경합:** snapshot 획득 후 switch hold 획득·해제, gate 재시작, 요청 진입 경합을 재현해 이전 epoch 요청이 실행되지 않는지 검증한다. 접수 응답 유실이나 부분 응답을 자동으로 재제출하지 않는다.
4. **M6 실제 모델별 검증:** 안전한 통합 환경에서 각 모델을 실제로 로드하고 ID, `/props`와 슬롯별 `n_ctx`, 최소 대화 및 필요한 reasoning·strict JSON schema 옵션을 모델·GGUF·빌드·template별로 확인한다. 확인하지 못한 조합은 미검증으로 남기며 해당 기능을 지원한다고 표시하지 않는다. 실제 운영 GPU 전환·후속 대화는 M8의 별도 완료 조건이다.

이 문서 작성 중 모델 전환, 서버 재시작, GPU 추론 요청 및 운영 설정 변경은 하지 않았다.

2026-11-10 읽기 전용 재확인: 운영 Qwen3.6 IQ2_M의 `/v1/models` meta `n_ctx=16384`와 `/slots` slot 0 `n_ctx=16384`가 일치했다. health는 ok, 해당 순간 슬롯은 유휴였다. 이는 해당 로드 모델 context 근거이며 다른 세 모델의 실제 context나 JSON schema/reasoning 호환 시험은 아니다.
