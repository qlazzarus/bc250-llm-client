# 채팅 컨텍스트 유지 현황과 개선 검토 자료

작성일: 2026-11-17 (Asia/Seoul)  
대상: `bc250-llm-client` 저장소의 일반 대화·롤플레잉 컨텍스트 관리  
용도: ChatGPT 채팅에 이 문서를 첨부해 설계를 검토하고, 합의한 구현 요구사항을 코딩 작업으로 전달한다.

## 1. 결론과 검토 범위

자동 요약 압축은 이미 구현되어 있다. 핵심 개선 과제는 **요약되지 않은 이력이 모델 입력에서 먼저 빠지는 상황을 줄이고, 요약 작업의 실패·중단·잘림에 안전하게 대응하는 것**이다.

이 문서는 로컬 소스 코드와 비밀정보가 아닌 일부 설정값을 확인한 결과다. 운영 서버 설정, 현재 로드된 모델, 실제 사용자의 대화 데이터, 실서비스 지연 시간과 요약 품질은 확인하지 않았다. 아래 문제는 코드 경로에서 확인한 위험이며, 실제 운영에서 발생했다는 의미는 아니다. 별도 표시한 제안은 아직 구현되지 않았다.

검토 대상은 이 프로젝트가 제공하는 채팅 서비스다. 이 문서를 읽는 ChatGPT 자체의 내부 컨텍스트 관리 방식에 관한 문서는 아니다.

## 2. 현재 구조

백엔드는 Python/FastAPI와 SQLite를 사용한다. 프런트엔드는 React/TypeScript이며, 모델 요청은 LLM gate의 OpenAI 호환 API를 통해 전달한다.

일반 대화의 입력 구성:

```text
모드별 system 지시문
→ 기존 대화 요약(system 메시지, 있을 때)
→ 요약 범위 이후의 최근 완료 대화(user/assistant)
→ 현재 사용자 질문(선택적으로 Wiki 참고자료 포함)
```

- 메시지 원문과 요약은 별도로 저장한다. 자동 요약은 원문 메시지를 삭제하지 않는다.
- 실패·취소된 생성 요청의 메시지는 일반적인 완료 이력과 구분해 입력에서 제외한다.
- 요약 범위는 `summary_up_to_message_id`로 기록한다. 이후 요청에서는 이 범위까지의 원문 대신 요약을 사용한다.
- 최근 이력은 DB에서 메시지 개수 제한을 적용해 가져온 뒤, 입력 예산에 맞춰 최신 턴부터 선택한다.
- 한 턴은 사용자 메시지와 뒤따르는 assistant 메시지 묶음이다. 예산이 부족하면 오래된 턴부터 제외한다.
- 대화 설정, 기존 요약, 현재 질문은 필수 입력이다. 이들만으로 예산을 초과하면 오류를 반환한다.
- 이미지 프롬프트 모드는 독립 요청으로 처리하며, 이전 이력과 요약을 사용하지 않는다.
- Wiki 검색·기억은 별도 기능이다. 대화 요약을 대체하지 않으며, 검색 자료도 입력 예산을 차지한다.

## 3. 설정과 토큰 계산

| 항목 | 코드 기본값 | 확인 사항 |
|---|---:|---|
| `MAX_HISTORY_MESSAGES` | 200개 메시지 | 로컬 `.env`는 **20**. 정상적인 user/assistant 쌍 기준 약 10턴 |
| `LLM_CONTEXT_TOKENS` | 16,384 | model control 사용 시 확인된 모델 컨텍스트와 설정 상한을 함께 적용 |
| `LLM_CONTEXT_SAFETY_TOKENS` | 512 | 안전 여유 |
| 답변 예약 토큰 | short 512 / medium 1,024 / long 2,048 | `MAX_COMPLETION_TOKENS` 상한 적용 |
| `ROLEPLAY_SUMMARY_TRIGGER_TOKENS` | 5,000 | 이름과 달리 일반 대화에도 적용 |
| `ROLEPLAY_SUMMARY_KEEP_RECENT_TURNS` | 6 | 최근 6턴을 요약 범위 밖에 유지 |
| `ROLEPLAY_SUMMARY_MAX_TOKENS` | 512 | 요약 출력 상한 |
| `MODEL_CONTROL_ENABLED` | false | 운영 서버의 실제 활성화 여부는 미확인 |

기본 입력 예산은 `컨텍스트 크기 - 답변 예약 토큰 - 안전 여유`다.

- 추정 함수는 `ceil(UTF-8 바이트 수 / 2)`를 사용한다. 실제 토크나이저 결과나 보장된 상한이 아니다.
- model control 활성 경로에서는 gate의 `/v1/chat/completions/input_tokens`로 실제 payload를 계수하고, 모델 epoch와 연결해 검증한다.
- 일반 채팅이 실제 예산을 초과하면 `fit_chat_payload()`가 오래된 턴을 제외하며 재검사한다.
- Wiki 사용 경로는 model control 여부와 별개로 먼저 추정 기반 `build_prompt(..., limit_context=True)`를 거친다. 이 과정에서 이미 제외한 이력은 후속 실측으로 복구되지 않는다.

## 4. 자동 요약의 수명 주기

1. 일반 대화 또는 롤플레잉 답변을 완료·저장한다.
2. `queue_roleplay_summary()`가 해당 대화의 진행 중 요약 작업 유무를 확인한다.
3. 기존 요약 범위 이후의 완료 이력에서 후보를 선택한다.
4. 기본적으로 이력이 6턴을 초과하고 추정 토큰이 5,000 이상이면 최근 6턴을 제외한 오래된 범위를 대상으로 삼는다.
5. `summary_jobs`에 작업을 저장하고 비동기 태스크를 시작한다.
6. 기존 요약과 새로 요약할 원문을 모델에 전달해 하나의 새 요약을 만든다.
7. 성공 시 요약과 커서를 함께 갱신한다. model control 경로에서는 실제 예산에 들어간 연속된 과거 턴 범위까지만 커서를 이동한다.

안전장치:

- 대화마다 `pending/running` 요약은 하나만 허용한다.
- 모델 교체 관련 대기·재검증 및 생성 동시성 제한을 공유한다.
- 요약 실패 시 기존 요약과 커서를 유지한다.
- 사용자가 요약을 수정하면 진행 중 작업을 실패 처리하고, 오래된 자동 결과가 수동 수정 내용을 덮어쓰지 않도록 검사한다.
- UI에 요약 진행·실패 상태를 표시하고, 설정 화면에서 요약을 직접 편집할 수 있다.

## 5. 확인된 문제와 영향

### P1. 메시지 개수 제한과 요약 임계값 사이의 공백

로컬 설정은 최근 20개 메시지만 읽지만, 요약 조건은 미요약 이력의 추정 5,000토큰이다. 짧은 대화가 누적되면 20개를 넘어도 요약 조건에 도달하지 않을 수 있다. 이때 이전 요구사항이 DB에는 남아 있어도 모델 입력에는 원문도 요약도 포함되지 않는다.

예: 짧은 11턴이 쌓이고 총 추정 토큰이 5,000 미만이면, 다음 질문의 이력 조회에서 첫 턴이 빠질 수 있다.

**제안:** 개수 제한에 의한 누락도 압축 판단 조건으로 포함한다. `20 → 200` 조정은 임시 완화책이며 근본 해결은 아니다.

### P1. 요약 시작 시점과 실제 채팅 예산의 불일치

요약은 답변 완료 후 시작한다. 시작 조건은 실제 질문·기존 요약·모드 설정·Wiki·답변 예약을 합친 예산과 직접 연결되지 않는다. model control 경로의 임계값 조정도 요약 출력 예약을 기준으로 한다.

또한 최근 6턴을 고정적으로 남겨, 6턴 이하의 긴 대화는 입력을 초과해도 요약 후보가 없다. 요약 진행 중 다음 질문이 들어오면 기존 요약과 제한된 이력으로 답한다.

**제안:** 최종 입력 예산을 기준으로 미리 압축하고, 오래된 미요약 턴을 제외해야 할 경우 요청 전 압축 여부를 판단한다. 최근 원문 유지 개수는 토큰 예산에 따라 줄일 수 있어야 한다. 압축 지연 시 대기할지, 누락을 알리고 답할지는 명시적으로 설계한다.

### P1. 비정상 종료 후 요약 작업 복구 누락

시작 코드에 남은 `summary_jobs.pending/running`을 복구하는 경로가 없다. 작업 상태만 남으면 새 요약을 큐에 넣는 검사와 유일 인덱스에 막혀 이후 자동 요약이 계속 중단될 수 있다.

**제안:** 시작 시 중단 작업을 복구하거나 실패 처리 후 재시도한다. 실제 실행 중인 작업과 중복되지 않도록 프로세스 운영 방식에 맞춘 소유권·실행 상태 정책이 필요하다.

### P1. 잘린 요약을 성공으로 저장할 가능성

요약 응답은 비어 있는지 검사하지만 `finish_reason=length` 여부를 확인하지 않는다. 내용이 일부라도 있으면 저장하고 커서를 이동할 수 있다. 이후 입력은 해당 범위 원문 대신 불완전한 요약에 의존한다.

**제안:** 잘린 출력은 커서를 이동하지 않는다. 더 작은 원문 범위로 재시도하고, 응답 구조·길이·유효성도 검사한다. 단순 구조 검사가 사실 보존까지 보장하지는 않는다.

### P2. 비활성 model control 경로의 요약 예산 계산 누락

`summary_candidate()`는 후보 원문 토큰만 계산한다. 실제 요청에 들어가는 기존 요약, 요약 지시문, 역할 라벨 등의 크기는 포함하지 않는다. model control이 꺼진 `run_summary_job()`에서는 완성된 payload를 다시 예산에 맞추지 않는다.

**제안:** 두 경로 모두 완성된 요약 payload로 예산을 검사한다. 실측할 수 없으면 여유를 둔 추정과 명시적인 한계를 사용한다.

### P2. 요약 품질·설명 가능성 개선

기존 요약을 계속 512토큰으로 다시 쓰므로 장기 대화에서 세부 요구사항이 소실될 가능성이 있다. 현재 테스트는 기능적 동작 중심이며 장기 기억 품질을 보장하지 않는다. UI도 특정 요청에서 몇 턴이 제외됐는지 보여주지 않는다.

**제안:** 목표·제약·확정 사항·미해결 사항을 구조화하고, 원문 출처 ID를 연결한다. 사용자 진술과 assistant의 제안·추측을 구분하고 최신 정정 사항을 우선한다. 요약은 대화 자료임을 명확히 해 원문 속 지시를 system 권한으로 승격하지 않도록 입력 경계를 설계한다. 해당 요청의 요약 범위·포함 턴·제외 턴·토큰 사용을 확인 가능하게 한다.

## 6. 권장 구현 순서

### 1단계: 데이터 보존과 복구

- 잘린 요약의 저장·커서 이동 방지.
- 중단된 요약 작업 복구 및 제한된 재시도.
- 전체 요약 payload의 예산 검사.
- 성공·실패·수동 수정·모델 변경 상황에서 요약과 커서 일관성 보장.

### 2단계: 예산 기반 압축

- 설정, 기존 요약, 현재 질문, Wiki, 출력 예약을 포함하는 공통 예산 계획 수립.
- 토큰 부족 또는 메시지 개수 제한으로 미요약 원문이 누락되기 전에 압축 판단.
- 최근 턴 보존을 고정 개수에서 예산 기반 정책으로 변경.
- 한 턴 자체가 요약 입력보다 큰 경우에도 진행 가능한 분할 정책 설계. 전체 턴을 다 처리하기 전에는 그 턴 이후로 커서를 이동하지 않는다.
- 백로그 압축은 요청마다 한 번만 처리할지, 제한된 횟수로 연속 처리할지 결정. 사용자 요청이 요약 때문에 기아 상태가 되지 않도록 제한.

### 3단계: 기억 품질과 사용자 확인

- 구조화된 요약과 원문 참조 도입.
- 반복 압축 품질 평가와 중요한 사실의 원문 재조회 검토.
- 컨텍스트 사용 현황 및 요약 재시도/재생성 UI 검토.
- 요약 삭제의 의미 정의: 커서를 유지해 과거를 잊는 동작인지, 커서를 초기화해 원문에서 다시 구성하는 동작인지 구분. 현재 수동 편집은 커서를 초기화하지 않는다.

처음부터 벡터 DB를 추가할 필요는 없다. SQLite 원문, 요약 범위, 최근 이력으로 보존과 복구 문제를 먼저 해결하고, 원문 검색 필요성을 평가한다.

결과: **38 passed**. 이 결과는 기존 테스트 통과를 의미하며 위의 모든 경계 상황을 검증했다는 뜻은 아니다. 실모델 품질 평가 및 운영 테스트는 하지 않았다.

## 8. 구현자가 볼 파일

경로는 저장소 루트 기준이다. ChatGPT에 이 문서만 첨부하면 아래 파일 자체는 보이지 않는다. 실제 수정안을 작성하려면 필요한 소스 파일을 추가로 제공한다.

| 파일 | 주요 내용 |
|---|---|
| `backend/app/prompting.py` | `estimate_tokens`, `build_prompt`, `summary_candidate`, `to_turns` |
| `backend/app/main.py` | `begin_generation`, `model_settings`, `check_payload_budget`, `fit_chat_payload`, `queue_roleplay_summary`, `run_summary_job`, `lifespan`, 대화 설정 수정 API |
| `backend/app/config.py` | 컨텍스트·출력·요약 설정 |
| `backend/app/db.py` | 대화 요약 필드, summary_jobs, 유일 인덱스와 마이그레이션 |
| `frontend/src/main.tsx` | 요약 편집·상태 표시·대화 로딩 |
| `tests/test_prompting.py` | 입력 구성 및 기본 요약 후보 테스트 |
| `tests/test_model_context.py` | 모델 컨텍스트와 실제 예산 검증 |
| `tests/test_summary_model_budget.py` | 요약 범위·모델 변경·실패 시 커서 보존 |
| `tests/test_api.py` | 완료 이력, 요약 설정 API 등의 통합 테스트 |

추가 공유 시 `.env`, API 키, 실제 개인 대화 DB는 첨부하지 않는다. 재현에는 비밀정보를 제거한 설정값과 합성 대화를 사용한다.

## 9. ChatGPT에 함께 보낼 요청문

```text

문서에 있는 현재 구현, 코드에서 확인한 위험, 미구현 제안을 구분해서 읽어줘.
```
