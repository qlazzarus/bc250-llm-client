# 대화·Wiki 퍼멀링크 개선 추천안 및 인수인계

작성: 2026-11-14 (Asia/Seoul)  
목표: 2026-11-15에 구현·검증을 마무리한다. 이 문서는 작업 예약이나 배포 완료를 뜻하지 않는다.

## 실제 문서 확인 결과

2026-11-14에 사용자가 지정한 `http://192.168.0.57/llm/#/wiki/2`의 통합 Wiki 문서 2를 앱의 읽기 API로 확인했다.

- 문서 ID: `2`, 분류: `general`, 제목: `AMD BC-250 AI 서버`, revision: `1`.
- 제목 필드에 `###`는 없다. 본문은 제목 필드와 별개이며, 서버 소개와 목록으로 구성된다. 출처 필드는 `ChatGPT`다.
- 화면에서 보인 `###`는 대화에서 사용한 마크다운 표기일 수 있다. 이를 DB의 실제 제목이나 본문 첫 줄로 가정하지 않는다.
- 이 문서의 추천 주소: `/llm/wiki/general/AMD%20BC-250%20AI%20%EC%84%9C%EB%B2%84`. 사람이 읽을 때는 `/llm/wiki/general/AMD BC-250 AI 서버`에 해당한다. 브라우저에 따라 한글이나 공백은 URL 인코딩 형태로 표시·복사될 수 있다.
- 제목은 문서 필드를 사용한다. 본문 첫 제목을 주소의 출처로 추측하거나 `AMD`로 임의 축약하지 않는다. 제목이 실제로 마크다운 문법을 포함하는 다른 문서는 변환 전 개별 확인이 필요하다. 문서 2를 포함해 기존 본문·제목을 자동 수정하지 않는다.

## 결론: 읽기 쉬운 경로와 변경되지 않는 문서 ID를 함께 사용

- 대화의 새 주소는 `/llm/chat/{conversation_id}`다.
- 통합 Wiki의 새 주소는 `/llm/wiki/{카테고리 경로}/{문서명}`이다. 예: `/llm/wiki/general/AMD BC-250 AI 서버`, `/llm/wiki/서버/하드웨어/AMD BC-250 AI 서버`.
- 문서 ID는 내부 식별자로 유지하고, 경로는 서버에서 ID로 해석한다. 목록·공유 버튼은 서버가 제공한 현재 경로를 사용한다. 프런트엔드에서 500개 문서 목록을 훑거나 검색 API의 상위 결과로 주소를 해석하지 않는다.
- 각 경로 구성요소의 표시명은 사용자가 읽을 수 있는 이름을 쓰고, 링크는 구성요소 단위로 URL 인코딩한다. 같은 주소의 비교·충돌 판정에는 명시적인 유니코드 정규화 규칙을 적용하되 기존 제목 데이터는 변경하지 않는다. 한글, 공백, `%`, `#`, `?`와 슬래시가 들어간 이름을 테스트한다.
- 문서명은 기본적으로 실제 제목 필드에서 생성한다. 주소용 이름을 별도로 편집할 수 있게 하는 기능은 우선 도입하지 않는다. 제목과 주소가 다른 `.../general/AMD` 형태는 사용자가 명시적으로 짧은 별칭을 요청한 경우에만 별도 설계한다.
- 같은 정규화 경로의 문서가 이미 여럿이면 임의의 첫 문서로 연결하지 않는다. 마이그레이션 사전점검에서 충돌을 보고하고, 충돌 문서별로 사용자가 확인할 수 있는 고유한 경로를 부여한다. 새 생성·이동 시에도 충돌을 명확히 안내한다. 기존 문서 생성·수정 자체에 새 제약을 무심코 추가하지 않도록 충돌 UI와 API를 함께 설계한다.

## 카테고리 계층과 주소 보존

현재 `wiki_documents.category`는 단일 문자열이며, 부모/자식 관계가 없다. 현재의 `/` 포함 문자열을 자동으로 분리하면 기존 카테고리의 의미가 바뀔 수 있다.

1. 카테고리를 부모 ID와 이름을 가진 명시적인 계층으로 표현하고, 문서는 카테고리를 참조하도록 마이그레이션한다. 카테고리 경로와 문서명은 각각 별도의 세그먼트로 만든다. 세부 카테고리는 필요한 깊이까지 지원하되 순환 및 형제 이름 충돌을 막는다.
2. 기존 `general`은 최상위 `general`로 보존한다. 기존의 다른 카테고리 문자열은 원칙적으로 각각 하나의 최상위 이름으로 보존하고, `/`를 자동으로 계층 구분자로 해석하지 않는다. 기존 데이터의 중복·특수문자·충돌을 읽기 전용으로 조사한 뒤 이전 계획을 확정한다.
3. 카테고리 변경·이름 변경과 문서 제목 변경은 문서 ID를 유지한다. 이전 경로를 해당 문서의 이력 경로로 보존하고 현재 경로로 안내한다. 다른 문서가 이미 쓰는 현재·이력 경로와 충돌하면 기존 링크를 탈취하지 않도록 변경을 거절하고 해결 방법을 보여 준다.
4. 삭제 문서의 이력 경로를 재사용하면 예전 링크가 다른 문서를 가리킬 수 있으므로, 최소한 예약된 삭제 경로로 남겨 잘못된 연결을 방지한다. DB 이행·삭제 정책은 구현 전 기존 삭제/복구 동작을 확인하고 테스트한다.
5. 목록에서는 카테고리 트리를 접고 펼칠 수 있게 한다. 검색 결과와 현재 문서가 속한 경로는 보이도록 펼치고, 검색을 초기화하면 전체 탐색으로 돌아갈 수 있게 한다.

기존 Wiki 검색 별칭은 검색을 위한 별도 기능이다. 주소 이력과 검색 별칭을 같은 것으로 취급하지 않는다. 별칭 중복·정규화 규칙 및 격리 문서 접근 제한도 기존 동작을 유지한다.

## 라우팅·기존 링크 호환

- 프런트엔드의 해시 라우팅을 History API 경로 기반으로 전환하고 `/llm/` 베이스를 일관되게 처리한다. 앱 내부 이동뿐 아니라 직접 진입, 새로고침, 브라우저 뒤로·앞으로, 모바일과 PC에서 같은 문서가 열려야 한다.
- 기존 `/#/chat/{id}`와 `/#/wiki/{id}`는 계속 열고, 성공적으로 식별한 뒤 새 정규 주소로 `replaceState`한다. 레거시 외부 Wiki 모드와 통합 Wiki 모드를 혼동하지 않는다.
- Wiki 본문의 기존 `#/wiki/{id}` 링크 및 새 경로의 같은 앱 내부 링크는 같은 화면에서 이동하고, 기존 Markdown 정화·외부 링크 정책을 유지한다. 다른 출처의 링크는 내부 Wiki로 가로채지 않는다.
- 편집 중 문서 링크 이동, 주소 변경, 뒤로·앞으로 및 대화로 돌아갈 때 기존 초안 보호와 충돌 처리 동작을 보존한다. 이동을 취소하면 화면과 주소가 일치해야 하며 비동기 응답이 늦게 도착해 다른 문서를 덮어쓰지 않아야 한다.
- 존재하지 않는 경로, 삭제된 문서, 접근 제한 또는 격리된 문서는 명확한 화면을 보여 준다. 중복 경로·잘못된 URL 인코딩도 안전하게 처리한다.
- 사용자가 제공한 운영 Caddyfile은 `handle /llm/api/*`를 FastAPI로 보내고 `handle_path /llm/*`에서 `try_files {path} /index.html`을 사용한다. 따라서 현재 구성이라면 `/llm/chat/...`와 `/llm/wiki/...`의 직접 진입은 SPA 셸로 전달될 것으로 예상된다. 운영 환경에서 실제 요청으로 검증하기 전까지는 확인된 배포 결과라고 보지 않는다. Caddy의 `/api/*`, Studio 및 기존 `/wiki/`는 건드리지 않는다.

## 내일 할 작업 순서

1. **읽기 전용 사전점검:** 실제 통합 Wiki의 제목·분류 경로 충돌과 기존 `/`, 공백, 한글, 예약문자, 정규화 충돌을 집계한다. 본문·민감정보는 불필요하게 출력하지 않는다. 문서 2가 위에서 확인한 제목과 분류를 유지하는지 다시 확인한다. 필요 시 백업·복구 계획을 먼저 확인한다.
2. **서버 및 데이터:** 카테고리 계층·경로/이력 등록 구조와 원자적인 마이그레이션을 구현한다. 기존 문서 ID·본문·revision·검색 별칭·격리 정책을 보존하고, 중복 경로는 명확히 처리한다. 인증된 경로 해석 API와 충돌·이력·삭제 동작을 구현한다.
3. **프런트엔드:** `/llm/chat/...`, `/llm/wiki/...` 경로 및 구 해시 호환, 카테고리 트리, 문서 링크 생성, 본문 내부 링크, 로딩·오류·초안 보호를 구현한다.
4. **자동 검증:** 경로 인코딩과 한글, 중복·정규화 충돌, 카테고리 이동, 제목 변경, 이력 경로, 삭제, 격리 및 권한, 마이그레이션 보존, 검색 결과, 구 링크, 브라우저 히스토리와 초안 취소를 테스트한다. 전체 백엔드 테스트와 프런트엔드 lint/test/build를 실행한다.
5. **운영 전 확인:** 사용자가 제공한 Caddy 구성에서 직접 URL·새로고침·뒤로/앞으로·옛 주소를 PC와 모바일에서 확인한다. 문서 2가 정확히 `/llm/wiki/general/AMD BC-250 AI 서버`에 대응하는지 확인한다. API 요청은 기존 인증·Host 정책을 사용한다. 운영 DB 백업 및 마이그레이션/복구 절차를 검토하고 실제 운영 배포 전 필요한 승인과 절차를 따른다.

## 완료 기준

- 대화와 Wiki 모두 새 경로로 직접 열고 새로고침할 수 있으며 기존 해시 링크가 작동한다.
- 문서 2의 실제 제목과 `general`이 표시·주소에 반영되고 제목이나 본문은 변형되지 않는다.
- 한 단계 및 다단계 카테고리, 충돌, 이름 변경, 삭제 이후에도 링크가 모호하거나 다른 문서로 잘못 연결되지 않는다.
- 수정 중 탐색 시 초안을 잃지 않고, 검색·권한·기존 외부 Wiki 동작이 회귀하지 않는다.
- 구현·테스트 결과와 실제 서버 및 모바일에서 확인하지 못한 항목을 명시한다.
