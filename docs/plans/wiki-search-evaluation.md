# Wiki 검색과 기억 검증

## D04 긴 문서 격리 평가 (2026-11-14)

운영 데이터나 실제 모델을 사용하지 않았다. 임시 SQLite에 D03 저장 경로로 만든 47,660자 가상 서버 문서와 격리 문서를 넣고 검색과 발췌를 확인했다. 같은 문서의 앞·중간·끝 질의 3개에서 문서 검색은 기존과 변경 후 모두 3/3이었다. 관련 문자열이 1,000자 발췌에 포함된 경우는 기존 1/3, 변경 후 3/3이었다. 기존에는 앞쪽 `BC250`을 먼저 찾아 중간의 냉각 설정과 끝의 백업 경로를 놓쳤다. 새 선택은 질문에 나타난 상대적으로 드문 단어를 우선하고 제목에 포함된 단어를 동률에서 뒤로 미룬다.

| 질의 | 문서 검색 | 기존 관련 발췌 | 변경 후 관련 발췌 | 변경 후 검색+발췌 p50/p95 |
| --- | --- | --- | --- | --- |
| BC250 일반 | 성공 | 성공 | 성공 | 0.97/2.05 ms |
| BC250 냉각설정 | 성공 | 실패 | 성공 | 1.00/1.11 ms |
| BC250 백업경로 | 성공 | 실패 | 성공 | 1.02/1.07 ms |

각 지연은 한 로컬 임시 DB에서 동일 질의를 30회 반복한 warm 측정이며 운영 지연이나 일반화된 품질 지표가 아니다. `bc250`, `bc-250`, `BC 250`은 이 fixture에서 같은 문서를 찾았고 무관 질의는 빈 결과였다. 자동 별칭은 만들지 않았다. 명시적 별칭 충돌, 오래된 문서의 200개 제목 검색 범위와 오탐 회귀는 기존 alias 테스트를 따른다.

1,000자 발췌 하나와 질문을 넣은 16,384 토큰 모의 설정에서 입력 추정 610, 출력 예약 512, 안전 여유 512로 합계 1,634였다. 추정치는 실제 모델 tokenizer 측정이 아니며 대화·요약 길이에 따라 결과는 달라진다. 예산에 맞지 않아 발췌를 제외한 경우 retrieved만 남고 provided·유효 cited에는 포함되지 않으며, 제외된 문서 인용은 invalid로 표시하는 테스트를 추가했다. 문서에 포함된 공격 지시가 비신뢰 참고자료라는 안내와 함께 전달되는 것을 확인했지만 실제 모델이 지시를 무시하는지는 검증하지 않았다.

발췌는 여전히 어휘 일치 기반이며 동의어·한국어 조사·반복되는 이름·여러 위치의 근거를 항상 식별하지 못한다. 각 질문 단어의 앞 32개 발생만 살피고, 문서당 1,000자 한 구간만 제공한다. 근거가 검색 또는 발췌에서 빠지거나 예산에서 제외될 수 있으며, 문서 ID 인용 일치는 사실성이나 답변과 근거의 의미적 일치를 보장하지 않는다. 실제 운영 문서, 모델 답변 품질과 부하는 미측정이다.

## I08 격리 검증 기록 (2026-11-13)

- 고정 소규모 자료 네 문서·질의 네 개에서 이전 FTS/부분 문자열 검색과 새 검색의 기대 문서 Top3 포함은 각각 4/4였고, 반환 집합도 각 질의에서 같았다. 동일 로컬 임시 DB에서 각 질의 25회 반복한 검색 p50/p95는 이전 0.095/0.138ms, 현재 0.225/0.329ms였다. 이는 매우 작은 warm fixture 결과이며 BC-250 운영 지연이나 일반화된 Recall을 뜻하지 않는다.
- 허용된 네 공유 속성의 양성 발언 5개는 모두 후보로 인식했고, 질문·부정·추측·계획·개인 대상·잘못된 포트의 음성 발언 7개는 후보로 인식하지 않았다. 이는 문장 매핑 fixture 결과이며 실제 사용 전체의 저장 precision/recall은 미측정이다. 중복·충돌·출처 삭제와 원자성은 별도 repository 테스트로 검증한다.
- 30개 임시 이력에 각 이전/새 본문 2,000자를 넣은 비교에서 기존 전체 응답은 370,770바이트, 요약 응답은 8,130바이트였다. 전송량 측정이며 실제 운영 트래픽이나 지연 수치가 아니다.
- 통합 자동 기억은 정규식 기반 매핑과 SQLite만 사용하며 추가 LLM 호출이 없다. 한 worker가 처리하고 DB에서 최대 32개씩 읽는 재시작 fixture 35건을 검증했다. 실제 GPU 사용량·foreground 지연 p50/p95·동시 사용자 부하는 측정하지 않았다.
- 4K/16K mock profile의 발췌 제외와 제공·유효 인용 구분, stream/nonstream·재조회, 문서 변경 후 스냅샷, 출처 카드의 1280×800·768×1024·390×844·320×568 레이아웃을 확인했다. 모델의 실제 인용 정확도와 주장·발췌의 의미 일치는 검증하지 않았다.

## 검색어·Alias 추가 평가 계획 (2026-11-12)

[검색어 정규화·Alias 계획](wiki-query-alias-plan.md)의 A01~A09와 W15-Q0~Q6를 평가 범위에 추가한다. `bc250`, `bc-250`, `BC 250`, `bc250 ai 서버` 및 조사·의문형 변형이 동일 문서를 찾는지 검증한다. 충돌 Alias, 유사 숫자, 이전 대화 혼입, MATCH 특수문자, 격리 문서와 거짓 인용도 포함한다.

기존/개선 결과는 같은 데이터·질의로 Recall@3, 무관 결과율, 질의별 성공/실패, p50/p95, SQL 횟수와 RSS를 비교한다. 검색 후보(retrieved), 실제 프롬프트 전달(provided), 답변 인용(cited) 및 주장과 발췌의 의미 일치는 별도 기록한다. 수용 기준은 연결 문서 §7을 따른다. 이번에는 계획만 추가했고 fixture 저장·테스트·운영 측정은 수행하지 않았다.

## 기존 평가 시나리오

운영 DB를 변경하지 않는 별도 테스트 Wiki에 아래 문서를 준비하고 각 질문의 기대 문서가 상위 3개에 나타나는지 확인한다. 문서 ID는 환경에 맞게 기록한다. 결과에는 검색 성공뿐 아니라 무관한 문서, 답변의 출처 및 오답도 기록한다. 비교 시 동일한 문서와 질문으로 기존 버전 및 개선 버전을 각각 실행한다.

| 테스트 문서 내용 | 대화 질문 | 기대 결과 |
| --- | --- | --- |
| 백업 경로: /srv/backup, 주기: 매일 | 백업 파일은 어디에 있어? | 백업 문서 |
| 백업 경로: /srv/backup, 주기: 매일 | 서버 백업 설정 알려줘 → 그 경로는? | 백업 문서 |
| 선호 음료: 홍차 | 내가 좋아하는 차가 뭐야? | 선호 문서 |
| 가족 여행 장소: 제주도 | 가족 여행지는 어디였지? | 여행 문서 |
| 서버 이름: BC250, 운영체제: Fedora | BC250의 운영체제는? | 서버 문서 |
| 프로젝트 배포 포트: 8010 | 배포 포트가 뭐야? | 배포 문서 |
| 고양이 이름: 나비 | 나비는 누구야? | 가족 문서 |
| Wi-Fi 비밀번호 없음 | 와이파이 비밀번호가 뭐야? | 없는 정보라고 답변 |
| 계획: 토요일 장보기 | 언제 장 보러 가기로 했지? | 일정 문서 |
| 문서 없음 | 없는 내용에 관한 질문 | 검색 결과 없음 또는 근거 없음 |

기억 테스트: 명시 요청, 현재 발언만으로 기억, 직전 발언을 가리키는 명시 요청, 정정 대상이 한 번만 존재하는 경우와 여러 번 존재하는 경우, 중복, 관련 문서 없음, 서버 연결 실패, 쓰기 응답 유실, 이미지·롤플레잉 제외를 각각 검증한다. 생성 결과뿐 아니라 실제 저장된 본문과 변경 전 기록을 확인한다. 비밀번호·인증정보 및 민감정보 요청의 저장 여부를 확인하되 모델의 지시 준수만으로 완전한 차단을 보장하지 않는다.

BC-250의 실제 문서와 질문 20~30개를 별도로 추가해 상위 3개 검색 성공률, 무관한 문서와 응답 지연을 기록한다. 민감한 운영 문서는 테스트 데이터에 복사하지 않는다. 실제 서버 결과는 아직 수집하지 않았다.
