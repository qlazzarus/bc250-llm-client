# Origin 기준 검토와 변경 잠금 계약 (미설치 후보)

이 문서는 M7 구현과 Linux 검증을 위한 계약이다. 현재 진단과 worker의 전환·복구·수동 확인 복구에는 잠금이 연결되어 있지만 배포자에는 연결되어 있지 않으므로 이 문서나 잠금 파일의 존재는 전환 허가 근거가 아니다. 기존 preflight의 거절을 유지한다.

## 독립 검토와 승격

- root가 관리하는 검토자는 실제 적용할 Caddy 설정, 모든 같은 origin의 경로·응답·실행 코드·정적 자산과 각 소유권·권한을 독립적으로 확인하고 정확한 manifest 바이트와 SHA-256을 승인한다. 배포자가 제공한 digest나 root 소유 파일이라는 사실만으로 검토를 대신하지 않는다. 일반 계정이 임의 manifest 또는 digest를 root 파일로 복사하도록 허용하는 sudo 규칙이나 API를 만들지 않는다.
- root 관리 승격 도구는 승인된 정확한 바이트와 digest의 대응을 확인하고 잠금을 잡은 상태에서 실제 배포와 기준 갱신을 수행해야 한다. 설치·교체 중 실패나 중단 후에도 이전 쌍으로 안전하게 복구하거나 불일치로 검사를 거절해야 한다. manifest와 anchor를 별도 파일로 바꾸는 작업은 원자적인 쌍 교체가 아니므로 잠금과 crash 복구가 필요하다. 갱신 후 고정 경로에서 다시 읽어 비교한다. 임시 파일·상위 디렉터리·ACL·심볼릭 링크 및 소유권도 보호해야 한다.
- Studio는 자기 산출물만 제출하고 별도 검토·승격할 수 있어야 한다. 공유 origin 전체 기준과 실제 Caddy 설정의 일관성은 확인하되 Client 또는 gate 재배포나 DB fence를 Studio 배포의 조건으로 삼지 않는다. 여러 프로젝트의 승격이 동시에 진행되면 공유 기준 갱신은 직렬화한다.

## 잠금 참여와 실패 처리

- Caddy 설정·관리 API, 같은 origin의 정적 자산과 backend 코드·실행 환경, manifest 및 anchor를 변경할 수 있는 모든 배포자와 관리자 경로는 같은 사전 생성 root 관리 inode에 `flock(LOCK_EX | LOCK_NB)`을 잡는다. 변경 전부터 완료·검증 또는 롤백 완료까지 잡고, 잠금이 없거나 바쁘거나 신뢰할 수 없으면 변경을 시작하지 않는다. 인자를 받아 임의 명령을 root로 실행하는 범용 잠금 래퍼는 만들지 않는다.
- 검사와 전환은 검사를 시작하기 전부터 전환의 마지막 보안상 필요한 단계까지 같은 잠금을 유지한다. 검사만 잠그고 전환 전에 놓으면 경합을 막지 못한다. 잠금이 바쁘거나, inode·anchor·manifest·설정·프로세스가 바뀌거나 확인이 불가능하면 실패한다. 각 작업의 실패 및 중단 경로에서도 잠금을 조기에 놓지 않도록 검증한다.
- 진단을 이미 잠긴 전환·복구 경로에 연결할 때는 잠금 보유자가 잠금 없는 내부 검사 함수를 호출해야 한다. 현재 `inspect_locked_origin()`은 직접 잠금을 취득하므로 잠긴 구간에서 다시 호출하면 자기 경합으로 실패한다. 잠금 없는 내부 함수는 독립적인 권한 판정이나 외부 호출 경로로 노출하지 않는다.
- **미해결 차단 조건:** systemctl restart 시간 초과 후 systemd job이 계속 실행될 수 있다. 현재 worker는 journal과 gate hold를 보존하고 복구 필요로 표시하지만 origin 잠금은 놓는다. 취소 방지 대기만으로 이 경우나 worker 종료를 해결할 수 없다. 검토용 `origin_deployment_guard()`는 공용 잠금을 잡고 고정된 root 관리 switch journal과 operation DB 사본을 확인하지만, gate hold 정합성을 보장하는 계약이 없어 검사 성공 후에도 변경을 무조건 차단한다. DB와 WAL/SHM의 신뢰·안정성을 검사하며 원본 DB에 쓰지 않는다. WAL 프레임과 commit 전체를 검증하지 않으므로 내용이 있는 WAL은 무조건 거절한다. 배포자 연결과 실제 Linux 검증이 필요하다. gate hold와 operation 기록 간 불일치 및 기록 정리 후 오류까지 이 판독만으로 확인할 수 없다. 이를 포함한 내구성 있는 barrier와 확인된 systemd settle·복구 완료 후에만 해제하는 경로를 구현해야 한다. 현재 배포자는 이 barrier에 참여하지 않으므로 전환을 활성화할 수 없다.
- 이 잠금은 협력적이다. 모든 쓰기 경로와 Caddy 관리 인터페이스가 신뢰되지 않은 계정에서 접근 불가능하고, 각 namespace에서 동일 inode를 보며 모든 합법적 변경자가 참여함을 실제 Linux에서 입증해야 한다. 하나라도 증명하지 못하면 전환은 차단한다.

## 이관 시 확인

M7에서 root 소유 설치 및 롤백 도구, Client·Studio·Wiki·Caddy의 모든 배포/관리 경로, 독립 검토 기록, 중단 복구와 권한을 구현하고 실환경 경합 및 일반 계정의 임의 승격 거절을 시험한다. 현재 `deploy/deploy-release.sh`는 기존 일반 계정 쓰기 경로이며 이 계약에 참여하지 않는다. 이 스크립트만 잠그거나 tmpfiles 템플릿만 설치하는 것으로 계약이 완성되지 않는다.
